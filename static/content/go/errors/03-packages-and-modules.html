Packages and Modules

A package is a directory of .go files that share a namespace. A module is a collection of packages versioned together, defined by a go.mod file. Together they form Go's code organization and dependency system.

Packages

// mathutil/mathutil.go
package mathutil

// Exported (capital letter): visible to other packages
func Double(n int) int { return n * 2 }

// unexported: private to this package
func helper() {}
// main.go
package main

import (
    "fmt"
    "example.com/hello/mathutil"
)

func main() { fmt.Println(mathutil.Double(21)) }
  • All files in a directory must declare the same package name.
  • Package main with func main() builds an executable; any other name is a library.
  • Import cycles are forbidden by the compiler.

Modules and go.mod

go mod init github.com/you/myapp
module github.com/you/myapp

go 1.24

require (
    github.com/google/uuid v1.6.0
    github.com/spf13/cobra v1.8.1
)

Dependencies

go get github.com/google/uuid@latest   # add or upgrade
go get github.com/google/uuid@v1.6.0   # pin a version
go mod tidy                            # sync go.mod/go.sum with your imports
go list -m all                         # list all dependencies
go mod vendor                          # optional: copy deps into ./vendor

go.sum holds cryptographic checksums of dependencies for reproducible, tamper-evident builds. Commit both go.mod and go.sum.

Recommended layout

myapp/
├── go.mod
├── go.sum
├── cmd/
│   └── myapp/
│       └── main.go          # thin entry point(s)
├── internal/                # private: cannot be imported by other modules
│   ├── server/
│   └── store/
├── pkg/                     # optional: public reusable libraries
└── README.md
internal/ is enforced

Code under internal/ can only be imported by code rooted at the parent of internal. It lets you keep implementation details private without worrying about outside users.

Import tricks

import (
    str "strings"        // alias
    _ "embed"            // import only for side effects
    . "fmt"              // dot import (avoid)
)

Naming conventions

  • Package names are short, lowercase, single words: http, store. Avoid util and common.
  • Avoid stutter: http.Server, not http.HTTPServer.
