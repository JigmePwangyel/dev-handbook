Shipping Go: Build and Docker

Go compiles to one static binary, which makes deployment unusually simple. This lesson ties Go back to the DevOps topic: cross-compiling, tiny container images and CI.

Building a release binary

CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o bin/server ./cmd/server
FlagEffect
CGO_ENABLED=0Pure Go, fully static binary with no libc dependency
-trimpathRemove local file paths (reproducible builds)
-ldflags="-s -w"Strip debug info: smaller binary

Cross-compilation

GOOS=linux  GOARCH=amd64 go build -o server-linux-amd64 .
GOOS=linux  GOARCH=arm64 go build -o server-linux-arm64 .
GOOS=darwin GOARCH=arm64 go build -o server-mac .
GOOS=windows GOARCH=amd64 go build -o server.exe .

Build for your Linux servers straight from a Mac, with no extra toolchain.

Multi-stage Dockerfile

# ---- build stage ----
FROM golang:1.24 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download            # cached layer unless dependencies change
COPY . .
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/server ./cmd/server

# ---- runtime stage ----
FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=build /out/server /server
EXPOSE 8080
USER nonroot
ENTRYPOINT ["/server"]

The final image contains only your binary: typically 10-25 MB instead of 800 MB+, with a minimal attack surface (no shell, no package manager). For even smaller images use FROM scratch, but you'll need to copy in CA certificates yourself if you make HTTPS calls.

Configuration the 12-factor way

cfg := struct {
    Addr string
    DSN  string
}{
    Addr: getenv("ADDR", ":8080"),
    DSN:  os.Getenv("DATABASE_URL"),
}

func getenv(k, def string) string {
    if v := os.Getenv(k); v != "" { return v }
    return def
}

Health checks and shutdown

  • Expose GET /healthz for liveness and /readyz for readiness (Kubernetes probes).
  • Handle SIGTERM with graceful shutdown so rolling deploys drop no requests.
  • Log to stdout as JSON with slog.New(slog.NewJSONHandler(os.Stdout, nil)).

CI with GitHub Actions

name: ci
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version-file: go.mod }
      - run: go vet ./...
      - run: go test -race -cover ./...
      - run: go build ./...

Add golangci-lint for deeper static analysis. See the Git & CI/CD section of the DevOps topic for pipelines in depth.

Capstone

  1. Take the todo API, persist data to SQLite or Postgres, and add structured logging and graceful shutdown.
  2. Write a multi-stage Dockerfile and confirm the image is under 25 MB.
  3. Add a GitHub Actions workflow that runs tests with -race and builds the image.
  4. Deploy it to a VPS or a Kubernetes cluster using what you learned in the DevOps topic.
