Generics

Since Go 1.18 you can write functions and types that work with many types while staying type-safe. Use them to remove duplication, not to build elaborate abstractions.

Generic functions

func Map[T, U any](xs []T, f func(T) U) []U {
    out := make([]U, 0, len(xs))
    for _, x := range xs {
        out = append(out, f(x))
    }
    return out
}

lengths := Map([]string{"a", "bb", "ccc"}, func(s string) int { return len(s) })
// [1 2 3]. Type arguments are inferred.

[T, U any] declares type parameters. any is the constraint, meaning "any type".

Constraints

import "cmp"

func Max[T cmp.Ordered](a, b T) T {
    if a > b { return a }
    return b
}
Max(3, 7)          // 7
Max("a", "b")      // "b"

// custom constraint: a union of types
type Number interface {
    ~int | ~int64 | ~float64
}
func Sum[T Number](xs []T) T {
    var total T
    for _, x := range xs { total += x }
    return total
}

The ~int means "int or any type whose underlying type is int" (such as type Age int). comparable is a built-in constraint for types usable with == and as map keys.

Generic types

type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }

func (s *Stack[T]) Pop() (T, bool) {
    var zero T
    if len(s.items) == 0 { return zero, false }
    v := s.items[len(s.items)-1]
    s.items = s.items[:len(s.items)-1]
    return v, true
}

var s Stack[string]
s.Push("a")
v, _ := s.Pop()

A generic set

type Set[T comparable] map[T]struct{}

func (s Set[T]) Add(v T)           { s[v] = struct{}{} }
func (s Set[T]) Has(v T) bool      { _, ok := s[v]; return ok }

When to use generics

Good fitPoor fit
Containers: stacks, queues, sets, cachesWhen an interface with methods already works
Slice/map helpers (Map, Filter, Keys)Only one concrete type is ever used
Same algorithm over numeric typesClever "type-level" programming
Look before you write

The standard library already provides generic helpers: packages slices, maps and cmp.
