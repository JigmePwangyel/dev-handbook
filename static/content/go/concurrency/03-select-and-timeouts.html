select and Timeouts

select is like switch for channels: it waits on multiple channel operations and runs whichever is ready first.

Basic select

select {
case msg := <-ch1:
    fmt.Println("from ch1:", msg)
case ch2 <- 10:
    fmt.Println("sent to ch2")
case <-time.After(1 * time.Second):
    fmt.Println("timeout")
}

If several cases are ready, one is chosen at random. If none is ready, select blocks.

Non-blocking operations

select {
case v := <-ch:
    fmt.Println("got", v)
default:
    fmt.Println("nothing ready")   // runs immediately if no case is ready
}

Timeouts

func fetchWithTimeout(url string) (string, error) {
    result := make(chan string, 1)   // buffered so the goroutine can't leak
    go func() { result <- slowFetch(url) }()

    select {
    case r := <-result:
        return r, nil
    case <-time.After(2 * time.Second):
        return "", errors.New("timeout")
    }
}

Tickers

ticker := time.NewTicker(500 * time.Millisecond)
defer ticker.Stop()
done := time.After(2 * time.Second)

for {
    select {
    case t := <-ticker.C:
        fmt.Println("tick at", t.Format("15:04:05"))
    case <-done:
        return
    }
}

The done-channel pattern

func worker(done <-chan struct{}, out chan<- int) {
    for i := 0; ; i++ {
        select {
        case out <- i:
        case <-done:
            return        // stop cleanly when asked
        }
    }
}

done := make(chan struct{})
go worker(done, out)
// ... later
close(done)               // broadcasts to every listener

Closing a channel wakes all receivers, so it works as a broadcast signal. This pattern is formalized by context (next lesson).
