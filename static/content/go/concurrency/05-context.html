Context

context.Context carries cancellation signals, deadlines and request-scoped values across API boundaries and goroutines. It is how Go programs stop work that is no longer needed.

Creating contexts

ctx := context.Background()                          // root, never cancelled

ctx, cancel := context.WithCancel(ctx)               // cancel manually
defer cancel()

ctx, cancel = context.WithTimeout(ctx, 3*time.Second) // auto-cancel after 3s
defer cancel()

ctx, cancel = context.WithDeadline(ctx, time.Now().Add(time.Minute))
defer cancel()

Always call cancel (usually with defer) to release resources.

Respecting cancellation

func work(ctx context.Context) error {
    for i := 0; i < 10; i++ {
        select {
        case <-ctx.Done():
            return ctx.Err()        // context.Canceled or context.DeadlineExceeded
        case <-time.After(500 * time.Millisecond):
            fmt.Println("step", i)
        }
    }
    return nil
}

ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
err := work(ctx)
fmt.Println(err)   // context deadline exceeded

Conventions

  • Pass ctx as the first parameter, named ctx: func Fetch(ctx context.Context, url string).
  • Don't store contexts in structs. Pass them through calls.
  • Derived contexts are cancelled when their parent is, forming a tree.
  • Pass context.TODO() when you haven't decided yet.

Contexts in the standard library

// HTTP client request with timeout
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
resp, err := http.DefaultClient.Do(req)

// database
rows, err := db.QueryContext(ctx, "SELECT ...")

// HTTP server: each request has its own context, cancelled if the client disconnects
func handler(w http.ResponseWriter, r *http.Request) {
    ctx := r.Context()
    // pass ctx to everything you call
}

Values

type ctxKey string
const requestIDKey ctxKey = "requestID"

ctx = context.WithValue(ctx, requestIDKey, "abc-123")
id, _ := ctx.Value(requestIDKey).(string)
Use values sparingly

Only for request-scoped metadata like trace IDs and auth identity. Never for optional function parameters. Use a private key type to avoid collisions.

Graceful shutdown

ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()

go func() { srv.ListenAndServe() }()

<-ctx.Done()   // wait for Ctrl+C or SIGTERM
shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
srv.Shutdown(shutdownCtx)   // finish in-flight requests, then exit

This is exactly what Kubernetes expects when it sends SIGTERM during a rolling deploy.

Try it

  1. Make an HTTP GET with a 1-second timeout against a slow endpoint (e.g. httpbin.org/delay/5) and print the error.
  2. Run 5 workers that all stop when you press Ctrl+C, using signal.NotifyContext.
