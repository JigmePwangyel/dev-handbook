Maps

A map is Go's built-in hash table: an unordered collection of key/value pairs with O(1) average lookup.

Creating and using maps

ages := map[string]int{
    "ada":   36,
    "linus": 54,
}
ages["grace"] = 85          // insert/update
fmt.Println(ages["ada"])    // 36
delete(ages, "linus")
fmt.Println(len(ages))

m := make(map[string][]string)  // empty, ready to use

The "comma ok" idiom

Reading a missing key returns the zero value, so you can't tell "missing" from "present with zero value" without the second return:

age, ok := ages["bob"]
if !ok {
    fmt.Println("bob not found")
}

if v, ok := ages["ada"]; ok {
    fmt.Println("found", v)
}

Iterating

for k, v := range ages {
    fmt.Println(k, v)
}
// order is intentionally randomized!

keys := slices.Sorted(maps.Keys(ages))  // sorted keys (Go 1.23+)
for _, k := range keys { fmt.Println(k, ages[k]) }

Rules and gotchas

  • Keys must be comparable: strings, numbers, bools, pointers, arrays, structs of comparable fields. Not slices, maps or functions.
  • A nil map can be read but not written. Writing panics. Always initialize with a literal or make.
  • Maps are not safe for concurrent writes. Protect with a sync.Mutex or use sync.Map.
  • Maps are reference-like: assigning one to another variable shares the same data.

Common patterns

// counting
counts := map[string]int{}
for _, w := range words { counts[w]++ }

// grouping
groups := map[string][]string{}
for _, p := range people { groups[p.City] = append(groups[p.City], p.Name) }

// set
seen := map[string]struct{}{}
seen["a"] = struct{}{}
if _, ok := seen["a"]; ok { /* present */ }

struct{} takes zero bytes, so map[T]struct{} is the idiomatic set.
