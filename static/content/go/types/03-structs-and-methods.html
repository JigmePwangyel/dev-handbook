Structs and Methods

Go has no classes. Instead you define structs (data) and attach methods (behavior) to any named type. Composition replaces inheritance.

Structs

type User struct {
    Name  string
    Email string
    Age   int
}

u := User{Name: "Ada", Email: "ada@example.com", Age: 36}
var z User              // zero value: all fields zero
fmt.Println(u.Name)
u.Age++
p := &u                 // pointer to struct
p.Name = "Ada L."       // auto-dereferenced

Methods

A method is a function with a receiver:

func (u User) Greeting() string {      // value receiver: works on a copy
    return "Hi, I'm " + u.Name
}

func (u *User) Birthday() {            // pointer receiver: can modify
    u.Age++
}

u.Birthday()
fmt.Println(u.Greeting())

Value or pointer receiver?

Use a pointer receiver when…Use a value receiver when…
The method modifies the receiverThe type is small and immutable (e.g. a point, a time)
The struct is large (avoid copying)It is a basic type or map/slice/func wrapper
The struct contains a mutex or similar

Rule of thumb: if any method needs a pointer receiver, use pointers for all methods of that type.

Constructors

Go has no constructors, only a convention: a NewX function.

func NewUser(name, email string) (*User, error) {
    if !strings.Contains(email, "@") {
        return nil, fmt.Errorf("invalid email %q", email)
    }
    return &User{Name: name, Email: email}, nil
}

Embedding: composition over inheritance

type Animal struct{ Name string }
func (a Animal) Speak() string { return a.Name + " makes a sound" }

type Dog struct {
    Animal          // embedded: Dog gets Animal's fields and methods
    Breed string
}

d := Dog{Animal: Animal{Name: "Rex"}, Breed: "Lab"}
fmt.Println(d.Name, d.Speak())   // promoted from Animal

// override by defining the method on Dog
func (d Dog) Speak() string { return d.Name + " barks" }

Struct tags

type Product struct {
    ID    int     `json:"id"`
    Name  string  `json:"name"`
    Price float64 `json:"price,omitempty"`
}

Tags are metadata read via reflection. The encoding/json package uses them (see the JSON lesson).

Exported vs unexported

Capitalized names (User, Name) are visible outside the package. Lowercase names are private to the package. That is Go's only access control.

Custom types and methods on any type

type Celsius float64
func (c Celsius) Fahrenheit() float64 { return float64(c)*9/5 + 32 }

type Color int
const (Red Color = iota; Green; Blue)
func (c Color) String() string { return [...]string{"Red", "Green", "Blue"}[c] }
fmt.Println(Green)   // prints "Green" because it satisfies fmt.Stringer
