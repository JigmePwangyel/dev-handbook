Cost Management and FinOps

In the data center, you spent money when you bought hardware. In the cloud, every engineer's API call can spend money, continuously. Without discipline, bills grow faster than revenue. FinOps is the practice of making cost visible, owned and optimised, by engineers as well as finance.

Why cloud bills surprise people

  • Elasticity cuts both ways: easy to create resources, easy to forget them.
  • Many meters: compute-hours, GB-months, requests, data transfer, per-endpoint hours.
  • Decentralised spending: any developer can launch a $5,000/month cluster.
  • Cost is lagging: you find out at month end.

The FinOps cycle is Inform (visibility and allocation), Optimise (cut waste, commit smartly), Operate (governance, continuous review). It is culture plus tooling.

Step 1: See the spend

  • Cost Explorer (AWS), Cost Management (Azure), Billing reports (GCP): group by service, account, region, tag.
  • Cost and Usage Report (CUR) exported to S3 and queried with Athena for the full detail.
  • Separate AWS accounts per environment/team: natural cost boundaries.
  • Third-party tools (Infracost for PRs, Vantage, CloudZero, Kubecost for K8s) add allocation and anomaly views.
# Last month's cost by service, from the CLI
aws ce get-cost-and-usage \
  --time-period Start=2026-09-01,End=2026-10-01 \
  --granularity MONTHLY \
  --metrics UnblendedCost \
  --group-by Type=DIMENSION,Key=SERVICE \
  --query 'ResultsByTime[0].Groups[].[Keys[0],Metrics.UnblendedCost.Amount]' \
  --output text | sort -k2 -nr | head

Step 2: Tagging for accountability

If you cannot say who owns a resource, nobody will turn it off. Define a mandatory tag set and enforce it:

TagExamplePurpose
teampaymentsChargeback / showback
servicecheckout-apiCost per product
envprod / staging / devFind non-prod waste
owneralice@acme.comWho to ask
expiry2026-11-01Temporary resources

Activate them as cost allocation tags in billing, apply them by default in Terraform, and enforce with Tag Policies/SCPs or policy-as-code:

provider "aws" {
  region = "eu-west-1"
  default_tags {
    tags = {
      team    = "payments"
      service = "checkout-api"
      env     = "prod"
      managed = "terraform"
    }
  }
}

Step 3: Budgets and alerts

  • AWS Budgets: monthly budget per account/tag with alerts at 50%, 80%, 100% of actual and forecasted spend, sent to email/Slack.
  • Cost Anomaly Detection: ML-flags unusual spikes (a runaway Lambda, a crypto-miner).
  • Per-environment guardrails: sandbox accounts with hard caps and auto-cleanup.
aws budgets create-budget --account-id 123456789012 --budget '{
  "BudgetName": "monthly-total",
  "BudgetLimit": {"Amount": "500", "Unit": "USD"},
  "TimeUnit": "MONTHLY",
  "BudgetType": "COST"
}' --notifications-with-subscribers '[{
  "Notification": {"NotificationType": "FORECASTED",
                   "ComparisonOperator": "GREATER_THAN",
                   "Threshold": 80},
  "Subscribers": [{"SubscriptionType": "EMAIL", "Address": "team@acme.com"}]
}]'

Step 4: Eliminate common waste

WasteFix
Idle / forgotten instances, dev environments running 24/7Schedule off nights/weekends (saves ~65%); auto-expire sandboxes
Over-provisioned instances (CPU under 10%)Right-size with Compute Optimizer / metrics
Unattached EBS volumes, old snapshots, unused Elastic IPsPeriodic cleanup, lifecycle policies (DLM)
NAT Gateway data processingVPC endpoints for S3/DynamoDB/ECR; one NAT per AZ only where needed
Data transfer out / cross-AZ chatterCloudFront, keep chatty services in the same AZ when safe, compress
S3 data never accessedIntelligent-Tiering, lifecycle to Glacier, expire logs, abort incomplete multipart uploads
Excessive log retention and high-cardinality metricsSet retention (e.g. 30 days), sample, drop debug logs in prod
Old generation instances / x86 onlyMove to current generation and ARM (Graviton): ~20% cheaper
gp2 volumesMigrate to gp3 (cheaper, tunable IOPS)
Oversized databases and unused read replicasRight-size; use Aurora Serverless v2 for variable loads

Order of operations: first remove waste and right-size, then commit. Committing to a bloated baseline locks in the waste. Cover the steady baseline (e.g. 60-70% of usage) with Savings Plans; leave the spiky remainder on-demand or spot.

Spot done right

  • Use for stateless, fault-tolerant work: CI runners, batch, workers, K8s node pools for non-critical pods.
  • Diversify across many instance types and AZs (capacity-optimised allocation).
  • Handle the interruption notice (checkpoint, drain). Keep an on-demand base for critical capacity.

Architecture is the biggest lever

  • Serverless / scale-to-zero for idle-heavy workloads; containers or reserved VMs for steady high load.
  • Caching and CDNs cut compute and egress.
  • Managed vs self-managed: include engineer time in the comparison; a cheap but pager-heavy setup is not cheap.
  • Efficiency in code: a slow query or N+1 can be a cost problem as much as a performance one.
  • Cost per unit (per customer, per 1k requests) is a better health metric than the total bill: growing bills are fine if unit cost is falling.

Review rhythm

  1. Weekly: anomaly alerts, top movers.
  2. Monthly: team showback review: what changed and why?
  3. Quarterly: commitment coverage, right-sizing sweeps, architecture reviews for top five cost drivers.
  4. In PRs: Infracost comments on Terraform changes show the monthly cost delta before merge.

Pitfalls

Classic horror stories

A leaked key mining crypto; an infinite Lambda loop triggered by its own S3 output; a debugging log level left on in prod; a forgotten GPU instance at $30/hour; a NAT Gateway moving terabytes of images. Budgets with alerts and anomaly detection exist for exactly these.

  • Optimising too early or too hard: engineer-weeks to save $20/month. Prioritise the top 5 line items.
  • Over-committing with 3-year plans before the architecture stabilises.
  • Cost-cutting that reduces reliability (single AZ, no backups). Know which savings are safe.
  • Free tier expiry catching learners after 12 months.
  • Ignoring data transfer in architecture diagrams.
  • No owner: untagged spend is nobody's problem.

Try it

  1. Open Cost Explorer, group the last 3 months by service, then by usage type for your top service. What surprised you?
  2. Create a monthly budget with forecast alerts to your email.
  3. Write a short script (or use aws ec2 describe-volumes --filters Name=status,Values=available) to list unattached EBS volumes, and find any idle load balancers or Elastic IPs.
  4. Add default_tags to a Terraform provider and run Infracost on a plan to see monthly cost for your change.
  5. Calculate: 10 instances at $0.10/h on-demand vs a 1-year Savings Plan at 35% off. What is the annual saving and what happens if you shrink to 5 instances after six months?
