What Is a Server?

A server is just a computer that runs a program waiting for requests, usually with no screen or keyboard, always on, reachable over a network. There is no magic: everything you do on a server is something you can do on a Linux laptop.

Why servers, and why Linux

Your laptop sleeps, changes networks and sits behind your home router. A server has a stable public IP address, runs 24/7 in a data centre with redundant power and networking, and is administered remotely. Roughly 90%+ of public cloud workloads and nearly all containers run Linux: it is free, scriptable, stable, secure and the target every tool in this handbook assumes. Learning it is the foundation of everything else.

Choosing a distribution

A distro bundles the Linux kernel with a package manager and defaults. For servers, pick something boring and widely documented.

DistroFamilyPackage toolNotes

DebianDebianaptVery stable, minimal
Rocky / AlmaLinuxRHELdnfFree RHEL-compatible; common in enterprises
Fedora ServerRHEL upstreamdnfNewer packages, short lifecycle

Recommendation

Use the latest Ubuntu LTS for this handbook. Always choose an LTS (long-term support) release for servers so you get security patches for years without forced upgrades. Commands for Rocky/Alma are noted where they differ.

Sizing a first server

  • 1 vCPU and 1-2 GB RAM runs a small Node/Python app plus nginx fine. A database plus app wants 2-4 GB.
  • Pick a region near your users. Pick SSD/NVMe disk. 25 GB is plenty to learn.
  • Check bandwidth/traffic allowance and whether snapshots/backups cost extra.

Getting your first VPS

  1. Create an account with a provider (Hetzner, DigitalOcean, Vultr, Linode, or an AWS Lightsail/EC2 free tier).
  2. Generate an SSH key on your laptop before creating the server (next lesson covers SSH deeply): 
    ssh-keygen -t ed25519 -C "you@laptop" -f ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub     # paste this PUBLIC key into the provider's form
  3. Create the server: choose Ubuntu LTS, a small plan, your region, and select your SSH key. Prefer key auth over a root password.
  4. Note the public IPv4 address the provider displays.

Connecting

ssh root@203.0.113.10                 # first login (some providers use "ubuntu" or "debian")
# The authenticity prompt appears once:
# "The authenticity of host ... can't be established. ED25519 key fingerprint is SHA256:..."
# Type "yes" to trust it; it's stored in ~/.ssh/known_hosts.

You are now typing commands on a computer in a data centre. Verify:

hostnamectl            # hostname, OS, kernel, virtualization type
cat /etc/os-release    # distro and version
uname -r               # kernel version
nproc; free -h; df -h  # CPUs, memory, disk
ip -br addr            # network interfaces and IPs
uptime                 # how long running, load averages

First 10 minutes on a new server

A fresh public server is scanned by bots within minutes. Do this immediately:

# 1. Update everything
apt update && apt upgrade -y

# 2. Create a normal user with sudo rights
adduser deploy
usermod -aG sudo deploy

# 3. Install your key for that user
rsync --archive --chown=deploy:deploy ~/.ssh /home/deploy

# 4. Test login in a SECOND terminal before closing the first
ssh deploy@203.0.113.10
sudo whoami           # should print "root"

# 5. Enable a firewall allowing SSH (and web later)
sudo ufw allow OpenSSH
sudo ufw allow 80,443/tcp
sudo ufw enable
sudo ufw status
Do not lock yourself out

Enable the firewall only after allowing SSH, and keep your existing session open while testing a new login. If you do get locked out, providers offer a web console and rescue mode.

The SSH lesson covers disabling root and password logins.

Pets vs cattle

A hand-configured server you nurse and fear to reboot is a pet. Servers that are created from a script, interchangeable, and replaced rather than repaired are cattle. This handbook starts with a pet to learn the mechanics, then moves toward cattle with scripts, containers and infrastructure as code. Keep notes of every command you run; those notes are your future automation.

Cost hygiene

  • Servers bill while they exist, even if idle. Delete what you no longer use.
  • Set a billing alert on cloud accounts, especially AWS/GCP.
  • Snapshots and unattached volumes and IPs also cost money.

Try it

  1. Create the cheapest Ubuntu LTS VPS you can, with your SSH key.
  2. SSH in and run the verification commands above; write down the kernel version, RAM and disk size.
  3. Do the "first 10 minutes" steps: new user, key, firewall.
  4. No spare money? Install Multipass (multipass launch --name lab) or Vagrant/UTM to get a local Ubuntu VM and follow along identically.
