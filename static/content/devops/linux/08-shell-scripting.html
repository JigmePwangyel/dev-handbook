Shell Scripting for Automation

A script is a saved list of commands that runs the same way every time. It is the first step from "I deployed it by hand" to "anyone (or any pipeline) can deploy it". The risk is that bash fails silently by default, so safe habits matter.

Why script

Manual steps get forgotten, mistyped and undocumented. A script is documentation that executes. Every CI job, Dockerfile RUN line, cron entry and cloud-init file is ultimately shell. Use bash for glue (30-200 lines); when logic gets complex (data structures, many branches, APIs) switch to Python or Go.

Your first script

#!/usr/bin/env bash
# hello.sh
name="${1:-world}"          # first argument, default "world"
echo "Hello, $name"
chmod +x hello.sh
./hello.sh Alice            # Hello, Alice
bash hello.sh               # also works without chmod

The first line, the shebang, selects the interpreter. #!/usr/bin/env bash finds bash on the PATH.

The safety header

By default, bash keeps going after errors, treats unset variables as empty and ignores failures in pipelines. That turns rm -rf "$BUILD_DIR/"* with a typo into a disaster. Start every script with:

#!/usr/bin/env bash
set -euo pipefail
IFS=$'\n\t'
OptionEffect
-eExit immediately if a command fails (nonzero status)
-uError on use of an unset variable
-o pipefailA pipeline fails if any stage fails, not just the last
IFS=$'\n\t'Split words on newline/tab only, safer with filenames containing spaces
set -xTrace: print each command as it runs (debugging; leaks secrets in logs)
set -e is not magic

It does not trigger inside if conditions, &&/|| lists or a !-negated command. Handle expected failures explicitly: grep -q foo file || true, or test with if.

Variables, quoting, defaults

APP_DIR=/opt/myapp                       # no spaces around =
readonly KEEP=5                          # constant
echo "Deploying to ${APP_DIR}/releases"  # braces delimit names
: "${DEPLOY_ENV:?DEPLOY_ENV must be set}"  # abort with message if unset/empty
PORT="${PORT:-3000}"                     # default value
files=(a.txt "b c.txt")                  # array
for f in "${files[@]}"; do echo "$f"; done   # quote "${arr[@]}" to preserve elements
now=$(date -u +%Y%m%d%H%M%S)             # command substitution
echo "${file%.txt}"                      # strip suffix; ${file##*/} = basename

Always quote expansions: "$var". Unquoted, a value with spaces or * gets split or globbed.

Conditionals, loops, functions

if [[ -f "$file" ]]; then echo "exists"; elif [[ -d "$file" ]]; then echo "dir"; else echo "no"; fi

[[ -z "$x" ]]        # empty            [[ -n "$x" ]]   # non-empty
[[ "$a" == "$b" ]]   # string equal     [[ $n -gt 5 ]]  # numeric greater
[[ -e path ]] [[ -r path ]] [[ -x path ]]   # exists / readable / executable
command -v docker >/dev/null 2>&1 || { echo "docker missing" >&2; exit 1; }

for i in 1 2 3; do echo "$i"; done
for f in /var/log/*.log; do wc -l "$f"; done
while read -r line; do echo "got: $line"; done < hosts.txt
until curl -fsS localhost:3000/healthz >/dev/null; do sleep 1; done   # wait for service

case "$1" in
  start)   echo "starting" ;;
  stop)    echo "stopping" ;;
  *)       echo "usage: $0 {start|stop}" >&2; exit 2 ;;
esac

log() { printf '%s [%s] %s\n' "$(date -Is)" "$1" "${*:2}"; }
die() { log ERROR "$*" >&2; exit 1; }
log INFO "started"

Use [[ ]] (bash) over [ ]. Scripts using #!/bin/sh must stick to POSIX features (no arrays, no [[).

Cleanup with trap

tmp=$(mktemp -d)
cleanup() { rm -rf "$tmp"; }
trap cleanup EXIT                        # runs on any exit, including errors
trap 'echo "failed at line $LINENO" >&2' ERR

Real example: a deploy script

Deploys a prebuilt tarball using the release-directory pattern: each version in its own folder, current is a symlink, switching is atomic and rollback is just re-pointing the link.

 /opt/myapp
 ├── releases/
 │   ├── 20261005101500/   (previous)
 │   └── 20261005113000/   (new)
 ├── shared/               (uploads, .env: survive deploys)
 └── current ─▶ releases/20261005113000

#!/usr/bin/env bash
# deploy.sh <artifact.tar.gz>
set -euo pipefail

APP_DIR=/opt/myapp
SERVICE=myapp
KEEP=5
HEALTH_URL="http://127.0.0.1:3000/healthz"

log() { printf '%s %s\n' "$(date -Is)" "$*"; }
die() { log "ERROR: $*" >&2; exit 1; }

[[ $# -eq 1 ]] || die "usage: $0 <artifact.tar.gz>"
artifact=$1
[[ -f "$artifact" ]] || die "artifact not found: $artifact"

# Prevent two deploys at once
exec 9>/tmp/myapp-deploy.lock
flock -n 9 || die "another deploy is running"

release="$APP_DIR/releases/$(date +%Y%m%d%H%M%S)"
previous=$(readlink -f "$APP_DIR/current" || true)

log "Unpacking to $release"
mkdir -p "$release"
tar -xzf "$artifact" -C "$release"
ln -sfn "$APP_DIR/shared/.env" "$release/.env"

log "Installing production dependencies"
(cd "$release" && npm ci --omit=dev)

rollback() {
  if [[ -n "$previous" && -d "$previous" ]]; then
    log "Rolling back to $previous"
    ln -sfn "$previous" "$APP_DIR/current"
    sudo systemctl restart "$SERVICE"
  fi
}

log "Switching current symlink"
ln -sfn "$release" "$APP_DIR/current"
sudo systemctl restart "$SERVICE"

log "Waiting for health check"
for i in $(seq 1 30); do
  if curl -fsS "$HEALTH_URL" >/dev/null; then
    log "Healthy after ${i}s"
    # prune old releases, keep newest $KEEP
    ls -1dt "$APP_DIR"/releases/*/ | tail -n +$((KEEP + 1)) | xargs -r rm -rf
    log "Deploy OK: $release"
    exit 0
  fi
  sleep 1
done

log "Health check failed"
rollback
die "deploy failed, rolled back"

Run it from your laptop or CI:

scp build.tar.gz web1:/tmp/ && ssh web1 '/opt/myapp/bin/deploy.sh /tmp/build.tar.gz'

Notice the DevOps principles at work: idempotent-ish steps, locking, health verification, automatic rollback, retained history, and logging with timestamps.

Best practices checklist

  • set -euo pipefail and quote everything.
  • Check prerequisites first (command -v), fail fast with clear messages to stderr.
  • Make scripts idempotent: safe to run twice (mkdir -p, ln -sfn, check-before-create).
  • Never hard-code secrets; read from environment or a root-only file.
  • Use mktemp and trap for temp files; never fixed names in /tmp.
  • Lint with ShellCheck (apt install shellcheck): it catches quoting bugs and more. Format with shfmt. Run both in CI.
  • Add --dry-run modes for destructive scripts, and print usage on bad input.
  • Avoid parsing ls; use globs or find -print0 | xargs -0.

Try it

  1. Write backup.sh that tars a directory into /var/backups/NAME-DATE.tar.gz, keeps only the 7 newest, and exits nonzero with a message on any failure.
  2. Run shellcheck on it and fix every warning.
  3. Adapt the deploy script to your app and test a failing health check to see the rollback work (hint: make /healthz return 500).
  4. Add a --dry-run flag that only prints the steps.
