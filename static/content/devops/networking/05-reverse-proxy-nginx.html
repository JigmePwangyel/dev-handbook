Reverse Proxies and nginx

A reverse proxy sits in front of your application and handles the messy edge of the internet: TLS, compression, static files, slow clients, rate limits. It is the first piece of infrastructure almost every production app gets, and nginx is the most common choice.

Forward vs reverse proxy

A forward proxy acts for clients (a corporate proxy hiding employees). A reverse proxy acts for servers: clients talk to it believing it is the site, and it forwards requests to one or more backends.

 Internet            ┌──────────── your server ─────────────────────────┐
                     │                                                  │
 Browser ──443──▶  nginx ──▶ 127.0.0.1:3000  Node app (API)
 (HTTPS)             │  ├──▶ 127.0.0.1:3001  Another service
                     │  └──▶ /var/www/site   static files (served directly)
                     └──────────────────────────────────────────────────┘

Why not just expose Node/Python/Java directly?

  • Privileged ports: nginx binds 80/443 while your app runs as an unprivileged user on 3000.
  • TLS termination: certificates, ciphers, HTTP/2 and HTTP/3 handled by battle-tested code.
  • Slow clients: nginx buffers a slow mobile client's upload/download so your app worker is not tied up ("slowloris" resistance).
  • Static files: nginx serves them via the kernel's sendfile orders of magnitude cheaper than your framework.
  • Compression, caching, rate limiting, access logs in one place.
  • Multiple apps on one IP: route by hostname or path.
  • Zero-downtime reloads and upstream failover.
  • Security boundary: malformed requests are rejected before reaching your code; the app is not directly reachable.

nginx basics

On Ubuntu: sudo apt install nginx. Layout:

PathPurpose
/etc/nginx/nginx.confMain config; includes the files below
/etc/nginx/sites-available/One file per site (Debian/Ubuntu convention)
/etc/nginx/sites-enabled/Symlinks to the enabled sites
/etc/nginx/conf.d/*.confExtra config snippets, also included
/var/log/nginx/access.log, error.logLogs. error.log is where 502s are explained.

Config is hierarchical: http { server { location { } } }. A request picks a server by port and server_name (matching the Host header), then a location by the best path match (exact =, longest prefix, then regex).

sudo nginx -t                     # ALWAYS test config before reloading
sudo systemctl reload nginx       # graceful: new workers start, old ones finish requests
sudo systemctl restart nginx      # drops connections; rarely needed
sudo tail -f /var/log/nginx/error.log

Example 1: the minimal reverse proxy

# /etc/nginx/sites-available/myapp
server {
    listen 80;
    server_name example.com www.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;

        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
sudo ln -s /etc/nginx/sites-available/myapp /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

Without the proxy_set_header lines your app sees Host: 127.0.0.1:3000 and every client as 127.0.0.1. Remember app.set('trust proxy', 1) in Express.

The trailing slash in proxy_pass

proxy_pass http://127.0.0.1:3000; forwards the original path unchanged. proxy_pass http://127.0.0.1:3000/; (with a URI part) replaces the matched location prefix. With location /api/ { proxy_pass http://127.0.0.1:3000/; } a request for /api/users arrives at the app as /users. This is the most common source of unexpected 404s behind nginx.

Example 2: a production-grade config

Full server with HTTPS, static files, compression, upstream keep-alive, caching of assets, security headers and timeouts:

# /etc/nginx/conf.d/rate-limit.conf  (http context; shared zones live here)
limit_req_zone  $binary_remote_addr zone=api:10m  rate=10r/s;
limit_req_zone  $binary_remote_addr zone=login:10m rate=5r/m;
limit_conn_zone $binary_remote_addr zone=perip:10m;

# WebSocket support: choose Connection header based on the Upgrade header
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}
# /etc/nginx/sites-available/myapp
upstream app_backend {
    server 127.0.0.1:3000;
    # server 127.0.0.1:3001;      # add more for load balancing
    keepalive 32;                 # reuse connections to the app
}

server {
    listen 80;
    server_name example.com www.example.com;
    # Let's Encrypt HTTP-01 and everything else redirects
    location /.well-known/acme-challenge/ { root /var/www/certbot; }
    location / { return 301 https://example.com$request_uri; }
}

server {
    listen 443 ssl;
    http2 on;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL:10m;

    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Content-Type-Options    "nosniff" always;
    add_header X-Frame-Options           "DENY" always;
    add_header Referrer-Policy           "strict-origin-when-cross-origin" always;

    client_max_body_size 10m;               # default 1m: uploads above get 413
    limit_conn perip 50;

    # --- Compression --------------------------------------------------
    gzip on;
    gzip_comp_level 5;
    gzip_min_length 1024;
    gzip_vary on;
    gzip_proxied any;
    gzip_types text/plain text/css text/javascript application/javascript
               application/json application/xml image/svg+xml;
    # Images/video are already compressed: do not list them.

    # --- Static files served directly by nginx ------------------------
    root /var/www/myapp/current/public;

    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
        access_log off;
    }

    # --- API with rate limiting --------------------------------------
    location /api/ {
        limit_req zone=api burst=20 nodelay;
        limit_req_status 429;
        proxy_pass http://app_backend;
        include /etc/nginx/snippets/proxy.conf;
    }

    location = /api/login {
        limit_req zone=login burst=3 nodelay;
        limit_req_status 429;
        proxy_pass http://app_backend;
        include /etc/nginx/snippets/proxy.conf;
    }

    # --- WebSockets ---------------------------------------------------
    location /socket.io/ {
        proxy_pass http://app_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header Host       $host;
        proxy_read_timeout 3600s;           # keep idle sockets open for an hour
        proxy_send_timeout 3600s;
    }

    # --- Everything else goes to the app -------------------------------
    location / {
        proxy_pass http://app_backend;
        include /etc/nginx/snippets/proxy.conf;
    }

    # Health endpoint not exposed publicly beyond the LB
    location = /nginx-health { access_log off; return 200 "ok\n"; }
}
# /etc/nginx/snippets/proxy.conf
proxy_http_version 1.1;
proxy_set_header Connection "";               # required for upstream keepalive
proxy_set_header Host              $host;
proxy_set_header X-Real-IP         $remote_addr;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_connect_timeout 5s;
proxy_read_timeout    60s;
proxy_send_timeout    60s;

What each part does

DirectiveWhy
upstream ... keepalive 32Avoids a TCP handshake per request to the app. Needs proxy_http_version 1.1 and an empty Connection header.
gzip_typesText compresses 70 to 90 percent; text/html is always on. Brotli needs a module; often done at the CDN.
expires 1y + immutableFor fingerprinted build assets. Never for HTML.
limit_req zone=api burst=20 nodelayAverage 10 req/s per IP, tolerate bursts of 20 immediately, reject the rest with 429.
Upgrade/Connection headersRequired for the HTTP Upgrade handshake that creates a WebSocket. Without it you get 400 or silent fallback to polling.
proxy_read_timeout 3600s for socketsDefault 60 s would kill idle WebSockets. (Or send app-level pings.)
always on add_headerOtherwise headers are omitted on error responses.

Example 3: serving a single-page app and an API

server {
    listen 443 ssl;
    http2 on;
    server_name app.example.com;
    # ssl_* omitted

    root /var/www/spa/dist;
    index index.html;

    location /api/ { proxy_pass http://127.0.0.1:3000; include snippets/proxy.conf; }

    location /assets/ { expires 1y; add_header Cache-Control "public, immutable"; }

    # index.html must not be cached long, so deploys take effect
    location = /index.html { add_header Cache-Control "no-cache"; }

    # Client-side routing: unknown paths return index.html
    location / { try_files $uri $uri/ /index.html; }
}

Example 4: several apps behind one nginx

server { listen 443 ssl; server_name api.example.com;    location / { proxy_pass http://127.0.0.1:3000; } }
server { listen 443 ssl; server_name admin.example.com;  location / { proxy_pass http://127.0.0.1:4000; } }
server { listen 443 ssl default_server; server_name _; ssl_reject_handshake on; }  # unknown hosts

Debugging nginx

SymptomLikely cause (check error.log)
502 Bad Gateway, "connect() failed (111: Connection refused)"App is down or on a different port/address
502, "upstream prematurely closed connection"App crashed mid-request or keep-alive mismatch
504, "upstream timed out"App too slow; raise proxy_read_timeout only if truly needed
413 Request Entity Too Largeclient_max_body_size
Wrong site servedNo matching server_name; falls to the default server
403 on static filesnginx user (www-data) cannot read the path (directory execute bits!)
Change not visibleForgot reload, or the browser/CDN cached the old response
Real IPs not loggedBehind a CDN/LB: use the realip module (set_real_ip_from, real_ip_header)

Useful: sudo nginx -T dumps the entire effective config; curl -I -H 'Host: example.com' http://127.0.0.1/ tests a vhost locally; custom log_format with $request_time and $upstream_response_time shows where latency is.

Caddy equivalent of Examples 1 plus HTTPS in full: example.com { reverse_proxy 127.0.0.1:3000 }. That is the whole file, and certificates are obtained and renewed automatically.

Try it

  1. Run a tiny backend: python3 -m http.server 3000 --bind 127.0.0.1. Install nginx and write Example 1 so http://your-server/ reaches it.
  2. Stop the backend and request the site. Find the matching line in error.log and the 502 in access.log.
  3. Add the /assets/ block and verify headers with curl -I.
  4. Add rate limiting rate=1r/s burst=2 and fire for i in $(seq 1 10); do curl -s -o /dev/null -w '%{http_code}\n' localhost/api/; done. See the 429s.
  5. Test the trailing-slash behaviour by logging the incoming path in a tiny app, with and without the slash on proxy_pass.
  6. Break the config on purpose and see nginx -t catch it before reload.
