Docker Architecture and Installation

"Docker" is really a stack of cooperating pieces: a CLI, a daemon, a high-level runtime (containerd), a low-level runtime (runc), and open standards that tie them together. Knowing which piece does what makes error messages, alternatives like Podman, and Kubernetes' move away from Docker all make sense.

ComponentRole
docker CLIThin client. Turns commands into REST calls. Contains no container logic.
dockerdThe daemon. Manages images, networks, volumes, the build system and the API. Runs as root.
containerdIndustry-standard runtime manager (a CNCF graduated project). Pulls images, manages snapshots and container lifecycle. Kubernetes can talk to it directly.
containerd-shimA small per-container process that keeps the container alive and holds its stdio even if containerd or dockerd restarts.
runcThe low-level runtime. Creates namespaces and cgroups, mounts the filesystem, then execs your process and exits.
The socket is root

The CLI talks to the daemon through /var/run/docker.sock. Anyone who can write to that socket can start a privileged container that mounts the host's /, which is effectively root on the host. Adding a user to the docker group is therefore equivalent to giving them passwordless root. Never mount the socket into a container unless you truly understand why.

The OCI standards

The Open Container Initiative defines vendor-neutral specifications so the ecosystem is not locked to Docker:

  • Image spec: the format of an image (manifest, config, layer tarballs).
  • Runtime spec: how to run an unpacked filesystem bundle (runc implements it).
  • Distribution spec: the HTTP API registries speak for push and pull.

Because of these, an image built with Docker runs on Podman, containerd, CRI-O, Kubernetes, AWS ECS and Cloud Run without changes.

Installing Docker

Mac and Windows: Docker Desktop (or alternatives)

Docker Desktop bundles the engine, CLI, Compose, BuildKit and a Linux VM with a GUI. Download it from docker.com. Note the licensing: it is free for personal use, education and small businesses, but larger companies need a paid subscription. Free alternatives include Colima (brew install colima docker, then colima start), Rancher Desktop and OrbStack.

Linux: Docker Engine

On Ubuntu or Debian, use Docker's official apt repository rather than the distribution's often outdated docker.io package. Follow the current steps at docs.docker.com/engine/install, which boil down to:

# Convenience script (fine for dev machines, review before running)
curl -fsSL https://get.docker.com -o get-docker.sh
less get-docker.sh
sudo sh get-docker.sh

# Run docker without sudo (log out and back in afterwards)
sudo usermod -aG docker $USER

# Start at boot
sudo systemctl enable --now docker

For production servers prefer the explicit apt repository setup so versions are pinned and auditable.

Verify

docker version        # client AND server sections; if server is missing the daemon is down
docker info           # storage driver (overlay2), cgroup version, runtimes
docker run --rm hello-world

hello-world exercises the full chain: CLI to daemon, daemon pulls the image from Docker Hub, containerd and runc run it, output streams back.

The core commands

Run

docker run nginx:1.27                      # foreground; Ctrl+C stops it
docker run -d --name web -p 8080:80 nginx:1.27   # detached, named, publish port
docker run -it --rm ubuntu:24.04 bash      # interactive shell, auto-remove on exit
docker run -e APP_ENV=dev -v "$PWD":/app alpine ls /app
FlagMeaning
-dDetached: run in background and print the container ID
-it-i keep stdin open, -t allocate a terminal. Needed for interactive shells
--nameHuman name instead of a random one such as quirky_turing
-p host:containerPublish a port (see networking lesson)
-e KEY=valSet environment variable
-vMount a volume or bind mount
--rmDelete the container when it exits; use for throwaway runs
--restart unless-stoppedRestart policy after crashes or daemon restarts

Inspect and manage

docker ps                 # running containers
docker ps -a              # include stopped ones
docker logs web           # stdout/stderr of the main process
docker logs -f --tail 100 web   # follow, last 100 lines
docker exec -it web sh    # open a shell in a running container
docker exec web nginx -t  # run a one-off command
docker stop web           # SIGTERM, then SIGKILL after 10s
docker start web          # restart a stopped container (same filesystem state)
docker restart web
docker rm web             # delete a stopped container (-f to force a running one)
docker images             # local images
docker rmi nginx:1.27     # delete an image
docker pull postgres:16   # download without running
docker system df          # disk usage
docker system prune       # remove stopped containers, dangling images, unused networks
stop vs. kill

docker stop sends SIGTERM and waits (default 10 seconds) so your app can shut down gracefully, then sends SIGKILL. If your container always takes exactly 10 seconds to stop, your process is ignoring SIGTERM, a classic sign that it is not PID 1-aware or that the shell form of CMD swallowed the signal. We fix that in the Dockerfile lesson.

The lifecycle

 image ──create──▶ Created ──start──▶ Running ──stop/exit──▶ Exited ──rm──▶ (gone)
                                        │  ▲                  │
                                        │  └─────start────────┘
                                        └─pause/unpause─▶ Paused

Stopping does not delete. A stopped container keeps its writable layer until docker rm, which is why docker ps -a accumulates clutter if you forget --rm.

A first real example

docker run -d --name web -p 8080:80 nginx:1.27
curl -i http://localhost:8080          # nginx welcome page
docker exec web cat /etc/nginx/nginx.conf | head
docker logs web                        # see your curl request logged
docker stop web && docker rm web

Kubernetes and Docker

Kubernetes removed its built-in "dockershim" in v1.24. Clusters now talk to containerd or CRI-O directly. Your Docker-built images still run perfectly, because they are OCI images. Only the node-level runtime changed.

Pitfalls

  • "Cannot connect to the Docker daemon": daemon not running, or your user lacks socket permission.
  • Disk full: images and stopped containers pile up. Schedule docker system prune (with care; -a also deletes unused images).
  • Using latest: unpredictable. Pin versions like nginx:1.27.
  • Apple Silicon surprises: pulling amd64-only images runs under slow emulation. Use --platform linux/amd64 deliberately.

Try it

  1. Install Docker and run docker run --rm hello-world. Read the explanatory output line by line.
  2. Start nginx as shown above on port 8080, curl it, view logs, then stop and remove it.
  3. Run docker run -d --name t alpine sleep 300 then time docker stop t. Why did it take about 10 seconds? Repeat with docker kill t.
  4. Run docker info | grep -i -E 'storage|cgroup|runtime' and identify the pieces from the diagram.
