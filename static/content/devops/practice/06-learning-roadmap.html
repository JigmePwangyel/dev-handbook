The Six-Month DevOps Learning Roadmap

DevOps is wide, and the most common mistake is learning tools in random order. This roadmap sequences topics so each month builds on the last, pairs every month with a concrete project and names the milestone that tells you you are done. It assumes roughly 8-10 hours a week and a working knowledge of programming.

Principles

  • Fundamentals before tools. Linux, networking and HTTP outlast every tool fashion. Kubernetes without them is cargo cult.
  • Build, do not just watch. For every hour of video, spend two hands-on. Break things deliberately.
  • One project that grows (the capstone) beats ten toy tutorials.
  • Depth over breadth early. Get good at one cloud (AWS is the most common), one CI system, one IaC tool.
  • Write it down. A blog or README per project is both learning and portfolio.

Overview

 M1 Linux+Git+Net ─▶ M2 Docker+CI/CD ─▶ M3 Cloud (AWS)+IaC ─▶ M4 Kubernetes ─▶ M5 Observability+Security ─▶ M6 Capstone polish+Cert+Jobs

Month 1: Foundations (Linux, Git, networking, scripting)

  • Learn: shell navigation, permissions, processes, systemd, journalctl, SSH keys, package managers, cron; bash scripting basics (set -euo pipefail, functions, loops); Git branching/rebasing/PR workflow; IPs, subnets, DNS, HTTP, TLS, ports, firewalls.
  • Project: rent a small VPS, harden it, deploy a simple app by hand with systemd and nginx, add HTTPS with Let's Encrypt.
  • Milestone: you can explain what happens from typing a URL to seeing a page, and you can diagnose "site is down" with ss, curl -v, dig, journalctl.
  • Resources: "The Linux Command Line" (William Shotts, free), OverTheWire Bandit wargame, Pro Git book (free), "Computer Networking: A Top-Down Approach" chapters 1-2, Julia Evans' zines.

Month 2: Containers and CI/CD

  • Learn: images, layers, Dockerfile best practices, volumes, networks, Compose; a registry; GitHub Actions (workflows, secrets, caching, matrix, environments); basic testing strategy; semantic versioning and trunk-based development.
  • Project: capstone stages 1-3: containerize an API + Postgres, CI pipeline that tests and pushes to GHCR, auto-deploy over SSH.
  • Milestone: a push to main reaches production automatically in under 10 minutes, with a one-command rollback.
  • Resources: Docker official docs "Get started", "Docker Deep Dive" (Nigel Poulton), GitHub Actions docs, Kelsey Hightower's talks, "Accelerate" by Forsgren/Humble/Kim (DORA metrics).

Month 3: Cloud (AWS) and Infrastructure as Code

  • Learn: IAM (users, roles, policies, least privilege), VPC (subnets, route tables, NAT, security groups), EC2, S3, RDS, ALB, Route 53, CloudWatch, Auto Scaling; Terraform (providers, state, modules, workspaces, remote backends); intro to Ansible for configuration.
  • Project: rebuild your capstone on AWS with Terraform: VPC, ALB, EC2/ECS Fargate, RDS in private subnets, DNS and TLS via ACM. Set a billing alarm first and destroy when finished.
  • Milestone: terraform apply creates the whole environment from scratch; you can draw its network diagram from memory.
  • Certification target: AWS Certified Solutions Architect - Associate (SAA-C03), or AWS Cloud Practitioner first if you want an easier warm-up.
  • Resources: AWS Skill Builder (free tier of courses), Adrian Cantrill's or Stephane Maarek's SAA courses, Tutorials Dojo practice exams, "Terraform: Up and Running" (Yevgeniy Brikman), HashiCorp tutorials.

Month 4: Kubernetes

  • Learn: architecture (control plane, kubelet, etcd), Pods, Deployments, Services, Ingress/Gateway API, ConfigMaps, Secrets, probes, resource requests/limits, HPA, PersistentVolumes, RBAC, namespaces, Helm, Kustomize, debugging (describe, logs, events, exec); GitOps with Argo CD or Flux.
  • Project: run the capstone on a local cluster (kind/minikube/k3d), then on k3s on a VPS or managed EKS/GKE with Helm and Argo CD; practise rolling updates, rollbacks and autoscaling.
  • Milestone: you can debug a CrashLoopBackOff, a Pending pod and a 503 from the ingress without guessing; you can explain why you would or would not use Kubernetes for a given workload.
  • Certification target: CKA (Certified Kubernetes Administrator), a hands-on, terminal-based exam: practise with killer.sh (included with the exam purchase) and Mumshad's KodeKloud labs. CKAD is the developer-focused alternative.
  • Resources: kubernetes.io tasks, "Kubernetes Up & Running", KodeKloud, "Kubernetes the Hard Way" (once).

Month 5: Observability, reliability and security

  • Learn: Prometheus + Grafana + Alertmanager, structured logging with Loki/ELK, OpenTelemetry tracing, SLIs/SLOs/error budgets, on-call, incident response and blameless postmortems; secrets management (Vault/SOPS), image scanning, SBOMs, signing, OWASP basics, backups and restore drills, load testing with k6.
  • Project: capstone stage 5 plus: dashboards and symptom-based alerts, an SLO for the API, a game day where a friend breaks something, a documented restore, Trivy and cosign in the pipeline.
  • Milestone: you have a written postmortem and a restore you timed.
  • Resources: Google SRE Book and SRE Workbook (free online), "Observability Engineering" (Majors et al.), Prometheus docs, Grafana University, OWASP Top 10.

Month 6: Polish, certify, get hired

  • Learn/practice: fill gaps found along the way; cost optimisation (FinOps basics); a second cloud's vocabulary; platform engineering ideas; Python or Go for tooling.
  • Project: publish the capstone repo with an excellent README, architecture diagram, runbook and a short write-up of what went wrong and what you learned. Optionally contribute to an open-source infra project.
  • Certification target: HashiCorp Terraform Associate (003) (inexpensive, achievable in 2-3 weeks after Month 3 work), plus the CKA or SAA if not already done.
  • Milestone: you can walk an interviewer through your project end to end, and answer the questions in the interview lesson.

Certs are not the goal

They are a structured syllabus and a way past resume filters. Employers value demonstrable projects and clear reasoning more. Pick one or two that match the jobs you want; do not collect them.

Study habits that work

  • Time-box: one weekday evening of theory, one of hands-on lab, one long weekend session on the project.
  • Keep a "things I broke" log; it is gold for interviews.
  • Use free tiers and budget alarms; always destroy cloud labs. A forgotten NAT gateway or load balancer costs real money.
  • Join a community (r/devops, CNCF and Kubernetes Slack, local meetups); explaining answers cements knowledge.
  • Read postmortems (the "post-mortems" GitHub list by danluu, Cloudflare and GitHub blogs): the best education in how systems fail.

Try it

  1. Write your own version of this roadmap with real calendar dates and the 3 hours you can protect each week.
  2. Choose your first certification and book the exam date now; a deadline changes behaviour.
  3. Create a public repo called devops-journal and commit a short note each week on what you built and what broke.
