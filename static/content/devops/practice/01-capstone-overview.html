Capstone Overview: Ship a Real Service End to End

Reading about DevOps does not make you a DevOps engineer; shipping does. In this capstone you will take a small API plus a Postgres database through every stage of the handbook: containerize it, build a CI pipeline, deploy to a real server with HTTPS, define the server with Terraform and watch it with Prometheus and Grafana.

The project

We will build Notely, a tiny notes API. The language does not matter; the examples use Node.js (Express) because it is compact, but a Python (FastAPI), Go or Java service works identically as long as it has three things: it reads config from environment variables, talks to Postgres and exposes /healthz and /metrics.

Prerequisites

  • Git and a GitHub account.
  • Docker Desktop (or Docker Engine + Compose v2) locally.
  • Node.js 22 LTS if you want to run the app outside Docker.
  • A cheap VPS (Hetzner, DigitalOcean, Vultr or AWS Lightsail; roughly 4-6 USD/month) and a domain name (or a free subdomain from DuckDNS / a spare domain).
  • Comfort with the Linux, Docker and CI/CD lessons earlier in the handbook.

Stage 0: write the app

Create the repo layout:

├── src/
│   ├── server.js
│   └── db.js
├── test/notes.test.js
├── migrations/001_init.sql
├── package.json
├── Dockerfile

├── .github/workflows/ci.yml

└── infra/             (Terraform)

// src/db.js
import pg from 'pg';
export const pool = new pg.Pool({
  connectionString: process.env.DATABASE_URL,   // factor III: config from env
  max: 10,
});
// src/server.js
import express from 'express';
import client from 'prom-client';
import { pool } from './db.js';

const app = express();
app.use(express.json());
client.collectDefaultMetrics();
const httpDuration = new client.Histogram({
  name: 'http_request_duration_seconds', help: 'request latency',
  labelNames: ['method', 'route', 'status'],
});
app.use((req, res, next) => {
  const end = httpDuration.startTimer();
  res.on('finish', () => end({ method: req.method, route: req.route?.path ?? req.path, status: res.statusCode }));
  next();
});

app.get('/healthz', async (_req, res) => {
  try { await pool.query('SELECT 1'); res.json({ status: 'ok' }); }
  catch { res.status(503).json({ status: 'db unavailable' }); }
});
app.get('/notes', async (_req, res) => {
  const { rows } = await pool.query('SELECT id, title, body, created_at FROM notes ORDER BY id DESC LIMIT 100');
  res.json(rows);
});
app.post('/notes', async (req, res) => {
  const { title, body = '' } = req.body ?? {};
  if (!title) return res.status(400).json({ error: 'title required' });
  const { rows } = await pool.query(
    'INSERT INTO notes (title, body) VALUES ($1, $2) RETURNING *', [title, body]);
  res.status(201).json(rows[0]);
});
app.get('/metrics', async (_req, res) => {
  res.set('Content-Type', client.register.contentType);
  res.end(await client.register.metrics());
});

const port = Number(process.env.PORT ?? 3000);
const server = app.listen(port, () => console.log(JSON.stringify({ level: 'info', msg: 'listening', port })));
process.on('SIGTERM', () => server.close(() => pool.end().then(() => process.exit(0))));
export default app;
-- migrations/001_init.sql
CREATE TABLE IF NOT EXISTS notes (
  id         BIGSERIAL PRIMARY KEY,
  title      TEXT NOT NULL,
  body       TEXT NOT NULL DEFAULT '',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

Install dependencies with npm init -y && npm i express pg prom-client, set "type": "module" and "start": "node src/server.js" in package.json, and commit to a new GitHub repo. Add a .gitignore containing node_modules and .env.

Use your own app if you have one

Any small service you already have works better than Notely because you care about it. Just make sure it meets the 12-factor checklist: config in env, logs to stdout, stateless, health endpoint.

Definition of done

  • git push to main runs tests, builds an image, publishes it and deploys it without manual steps.
  • https://notely.yourdomain.com/healthz returns 200 with a valid certificate.
  • The server can be destroyed and recreated from Terraform plus one bootstrap script.
  • Grafana shows request rate and latency; an external check alerts you when the site is down.
  • A nightly database backup exists off the server, and you have restored it once.
  • A README documents how to run, deploy, roll back and restore.

How to get the most out of it

  • Commit after every step with clear messages; your git history becomes your portfolio story.
  • Break things on purpose (kill the container, fill the disk, push a failing test) and watch what the system does.
  • Write the README as if a stranger had to operate it at 3 a.m.
  • Stretch goals: swap compose for k3s/Kubernetes, add a staging environment, add blue-green deploys, add Trivy and cosign, add a managed database.

Try it

  1. Create the repo and the app above, start a local Postgres with docker run -e POSTGRES_PASSWORD=pw -p 5432:5432 postgres:17, apply the migration with psql and run the API with DATABASE_URL=postgres://postgres:pw@localhost:5432/postgres npm start.
  2. Verify with curl -X POST localhost:3000/notes -H 'content-type: application/json' -d '{"title":"hello"}' then curl localhost:3000/notes.
  3. Reserve your VPS and domain now, since DNS and account verification can take time.
